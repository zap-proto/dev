# Ecosystem

Open-source services that depend on ZAP directly. The list below is grepped from public `go.mod` / `Cargo.toml` / `package.json` files and verified to actually link ZAP packages (not just mention them in docs).

## Native ZAP RPC

Services that use `github.com/zap-proto/go` directly as their application protocol.

| Service | Repo | Role |
|---|---|---|
| **Hanzo PubSub** | [hanzoai/pubsub](https://github.com/hanzoai/pubsub) | Native ZAP RPC for the pubsub control plane; payload framing on the data plane |
| **Hanzo Storage** | [hanzoai/storage](https://github.com/hanzoai/storage) | Native RPC between storage shards; capability-passing for cross-shard reads |
| **Hanzo Tasks** | [hanzoai/tasks](https://github.com/hanzoai/tasks) | Native RPC between scheduler ↔ worker pool; task handles are ZAP capabilities |
| **Hanzo Playground** | [hanzoai/playground](https://github.com/hanzoai/playground) | Sandboxed runner ↔ host control surface |
| **Hanzo Base-HA** | [hanzoai/base-ha](https://github.com/hanzoai/base-ha) | Cross-replica state-machine replication |

## HTTP over ZAP

Services using [`zap-proto/http`](https://github.com/zap-proto/http) — the `net/http` drop-in.

| Service | Repo | Role |
|---|---|---|
| **Hanzo Gateway** | [hanzoai/gateway](https://github.com/hanzoai/gateway) | API gateway terminating user HTTP, proxying upstream over ZAP-HTTP |
| **Hanzo Ingress** | [hanzoai/ingress](https://github.com/hanzoai/ingress) | L7 reverse proxy, serves ZAP-HTTP on the cluster-internal hop |
| **Hanzo Cloud** | [hanzoai/cloud](https://github.com/hanzoai/cloud) | Unified control plane — one binary, 15+ subsystems on a sub-1,000-line [zip](/docs/zip) compose root, zero gRPC/protobuf in app code |
| **Lux ZAP** | [luxfi/zap](https://github.com/luxfi/zap) | Lux-network reference integration |

## Adding your service

If you're shipping a public service or library that links ZAP packages, open a PR against [zap-proto/dev](https://github.com/zap-proto/dev) — single line in this ecosystem page. We don't gatekeep; we just want a public repo + a real `go.mod` / `Cargo.toml` / `package.json` entry.

Production but private deployments are tracked separately under the case-studies workstream — reach out at hello@zap-proto.io.

## Performance reference points

These deployments share their numbers on the [benchmarks page](/docs/benchmarks):

- **Hanzo Gateway** — 1.1M req/s per gateway pod (8 cores), p99 < 200 µs at the edge
- **Hanzo PubSub** — 1.8M msg/s per broker, 22 µs p99 fan-out latency
- **Hanzo Tasks** — task-handle capability passing across 10k concurrent workers, no serializer hot spot
