# Protocols

ZAP is a wire format and capability-based RPC system. You can use it two ways:

1. **Natively** — define your own `.zap` interfaces and let ZAP be the application protocol. This is the fastest path and the only one that gives you ZAP's full capability model (transferable, revocable references instead of bearer tokens).
2. **As a carrier** — run a higher-level protocol (HTTP, MCP, FIX, …) on top of ZAP framing. Existing semantics, zero-copy buffers underneath, mutual KEM auth at the transport.

## Choices

| Protocol | Page | When to use |
|---|---|---|
| **Native ZAP RPC** | [native](/docs/protocols/native) | Greenfield service ↔ service, you want capabilities + min latency |
| HTTP | [http](/docs/protocols/http) | Drop-in `net/http` replacement, existing HTTP clients keep working |
| MCP | [mcp](/docs/protocols/mcp) | Agent tool-call channel, replaces stdio MCP |
| A2A | [a2a](/docs/protocols/a2a) | Cross-vendor agent collaboration (Google A2A spec) |
| ACP | [acp](/docs/protocols/acp) | FIPA-style structured speech acts between agents |
| RNS | [rns](/docs/protocols/rns) | Service discovery bound to identity, not DNS |
| FIX | [fix](/docs/protocols/fix) | FIX 4.4 / 5.0 trading, sub-µs p99 |
| WS | [ws](/docs/protocols/ws) | Multi-stream pubsub, per-stream FEC, no head-of-line blocking |

## Why carry HTTP / MCP / FIX over ZAP at all?

If you already speak HTTP, why pipe it through ZAP? Because the carrier buys you things the higher-level protocol can't:

- **Zero-copy at every hop** — the payload sits in shared-memory buffers from network read to handler dispatch. No serializer step between layers.
- **One auth model** — mutual KEM-bound identity at the transport. The higher-level protocol inherits authentication; no per-layer JWT, no API keys, no cookies.
- **One observability model** — every frame is signed and content-addressed. Wireshark sees the same flow your application sees.
- **One framing layer** — multi-stream, FEC, no head-of-line blocking. The higher-level protocol doesn't re-invent it.

## Picking the right one

| You need | Use |
|---|---|
| New internal service, full control of both ends | [Native ZAP RPC](/docs/protocols/native) |
| Drop-in replacement for `net/http.Handler` | [HTTP](/docs/protocols/http) |
| Agent tool-call channel | [MCP](/docs/protocols/mcp) |
| Cross-vendor agent messaging | [A2A](/docs/protocols/a2a) or [ACP](/docs/protocols/acp) |
| Service discovery bound to identity | [RNS](/docs/protocols/rns) |
| Sub-µs trading | [FIX](/docs/protocols/fix) |
| Pubsub with FEC | [WS](/docs/protocols/ws) |

All Go reference implementations live under [github.com/zap-proto](https://github.com/zap-proto); polyglot clients speak them via the per-language [SDKs](/docs/sdks).
